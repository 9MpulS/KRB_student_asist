# Як генерувати документацію

Цей проєкт використовує **MkDocs** зі стилем **Material** та плагіном **mkdocstrings** для автоматичної генерації документації безпосередньо з коментарів у коді (досстрінгів) формату **Google**.

## Попередні вимоги

Переконайтеся, що ви встановили всі залежності середовища для розробки за допомогою `uv`:

```bash
uv sync
```

## Перегляд документації локально (Live Reload)

Швидкий спосіб перевірити, як виглядає ваша документація під час її написання — це запустити локальний сервер, який оновлюватиметься автоматично при будь-яких змінах файлів (конфігурацій, розмітки `.md` чи самого коду Python).

```bash
uv run mkdocs serve
```

Після цього відкрийте браузер і перейдіть за адресою: [http://127.0.0.1:8000](http://127.0.0.1:8000)

## Генерація статичних HTML-файлів

Якщо вам потрібно згенерувати фінальні статичні файли (наприклад, для хостингу на звичайному веб-сервері або у вигляді архіву), виконайте наступну команду:

```bash
uv run mkdocs build
```

Ця команда створить директорію `site/` у корені проєкту. Ця директорія міститиме всі згенеровані HTML, CSS та JavaScript файли.

## Додавання нових сторінок

1. Створіть новий `.md` файл у директорії `docs/` (або в її піддиректоріях).
2. Відкрийте файл `mkdocs.yml` у корені проєкту.
3. Додайте посилання на ваш новий файл у розділ `nav:` відповідно до того, де ви хочете, щоб він відображався у меню.

## Як документувати код Python

Ми використовуємо стандарт **Google Docstrings**. Щоб клас чи функція з'явилася в документації, додайте до неї коментар і розмістіть спеціальний тег у відповідному Markdown-файлі:

```markdown
::: src.api.routes.questions.ask_question
```
MkDocstrings автоматично витягне документацію для функції `ask_question`.
