# Короткий огляд інструментів генерації документації для Python

Для створення якісної документації до проєктів мовою Python існує кілька популярних інструментів, кожен з яких має свої переваги:

1. **Sphinx**
   - *Опис*: Найпопулярніший та найстаріший інструмент документації Python, що використовує формат reStructuredText (reST). Спочатку був створений для документації самого Python.
   - *Переваги*: Дуже потужний, підтримує перехресні посилання, має величезну екосистему розширень, ідеально підходить для складних монолітних систем.
   - *Недоліки*: Крута крива навчання, синтаксис reST є менш інтуїтивним порівняно з Markdown, складне налаштування.

2. **MkDocs**
   - *Опис*: Швидкий та простий генератор статичних сайтів, що орієнтований на створення проектної документації за допомогою Markdown.
   - *Переваги*: Просте налаштування, пишеться в Markdown (який всі знають), швидке генерування сторінок. Модуль `mkdocs-material` забезпечує сучасний, зручний інтерфейс "з коробки" (включно із пошуком та підтримкою мобільних пристроїв). Плагін `mkdocstrings` дозволяє витягувати докстрінги з Python коду.
   - *Недоліки*: Дещо обмеженіший за Sphinx у складних перехресних посиланнях між масивними бібліотеками.

3. **pdoc** (та pdoc3)
   - *Опис*: Інструмент, який автоматично генерує API документацію з Python модулів без необхідності будь-яких конфігураційних файлів.
   - *Переваги*: Працює "з коробки", нульова конфігурація.
   - *Недоліки*: Менш гнучкий у налаштуванні вигляду, складно додавати об'ємні ручні туторіали і керівництва користувача, дизайн за замовчуванням може виглядати застарілим.

4. **FastAPI (Swagger UI/ReDoc)**
   - *Опис*: Фреймворк FastAPI автоматично генерує документацію для API за стандартом OpenAPI.
   - *Переваги*: Не потребує зайвого коду, інтерактивний (дозволяє надсилати HTTP запити прямо з документації).
   - *Недоліки*: Покриває виключно API-прошарок застосунку, не підходить для документування внутрішньої бізнес-логіки та загальної архітектури.

## Вибір для даного проєкту
Для нашого проєкту ми використовуємо комбінацію **MkDocs (з Material Theme та mkdocstrings)** та вбудовану документацію **FastAPI Swagger**.
MkDocs дозволяє нам легко вести загальну проектну документацію у звичайному форматі Markdown і водночас автоматично генерувати API документацію для наших внутрішніх класів та функцій, використовуючи стандарт **Google Docstring Format**, завдяки його високій читабельності.
FastAPI буде використано для надання інтерактивного OpenAPI Swagger-інтерфейсу для клієнтів.
